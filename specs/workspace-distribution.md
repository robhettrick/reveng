# Workspace Distribution — Specification

## Overview

A redesign of how reveng's agents and skills reach the project being analysed. Today they live in `~/.config/reveng/plugin/` and are loaded into Claude Code via the `--plugin-dir` flag at every invocation. This proposal shifts to a per-workspace copy model: `reveng init` populates `$PWD/.claude/agents/` and `$PWD/.claude/skills/` directly, and the runner relies on Claude Code's built-in discovery of project-level `.claude/`.

## Motivation

The current model is functional but opaque. The agents and skills that reveng installs are hidden under `~/.config/reveng/plugin/` — invisible to anyone reading the workspace, and tied to a CLI-specific flag (`--plugin-dir`) that no one inspecting the project would discover. Discoverability is the primary driver: when a developer opens a reveng workspace in their editor or runs `ls -la`, the available agents and skills should be visible alongside the rest of the workspace contents.

User-level installation (`~/.claude/agents/`) was considered and rejected: reveng's agents should appear *only* when working on a reveng workspace, not in every Claude Code session a developer runs.

## Design

### `reveng init`

`init` retains its current responsibilities (scaffold workspace dirs, update `.gitignore`) and gains three new ones:

1. **Copy agents and skills.** Read from `~/.config/reveng/plugin/{agents,skills}/` and write to `$PWD/.claude/{agents,skills}/`.
2. **Write a workspace CLAUDE.md.** Place a reveng-authored CLAUDE.md at the workspace root describing the workspace layout — what `screenshots/`, `transcripts/`, `src/`, and `output/` are for. This file is static and ships with reveng; it is **not** generated by Claude Code's `/init` skill, because the reveng workspace is an aggregate working directory and not a code repository, so `/init` would misread the structure.
3. **Extend `.gitignore`.** Add `.claude/` alongside the existing entries (`output/html/`, `output/transcripts/*_curated.*`). Reveng-installed agents and skills are treated as ephemeral scaffolding; the workspace's CLAUDE.md is not gitignored.

#### Conflict policy

If any file at the destination already exists, **skip it and print a warning**. The reveng workspace is normally a fresh directory, but `reveng init` may be re-run, and the user may have edited an agent locally. Skipping protects local edits at the cost of stale agents — the user resolves manually by deleting the file and re-running init.

The warning lists each skipped path, e.g.:

```
Skipped (already exists): .claude/agents/business-analyst/AGENT.md
Skipped (already exists): .claude/skills/validate-mermaid/SKILL.md
```

Reveng's agents and skills both use the directory + capitalised-entry-file pattern (`agents/<name>/AGENT.md`, `skills/<name>/SKILL.md`) so that agent-specific supporting files (templates, fragments) can live alongside the entry file as the workspace evolves.

### Runner

The runner drops `--plugin-dir` entirely. Commands become:

```bash
claude -p "<prompt>" --dangerously-skip-permissions --output-format stream-json --verbose --model "$MODEL"
```

**Preserved behaviour:**

- `--dangerously-skip-permissions` stays. The runner is designed for headless, non-interactive use and Claude needs unrestricted tool access to write outputs.
- The existing `warn_permissions` check stays. Before each `claude` invocation, if `$DEVCONTAINER != "true"` (i.e. not inside a reveng sandbox), the runner prints a loud multi-line warning to stderr noting that Claude is running with unrestricted tool access outside a container. This is a safety nudge, not a block — power users can still run on the host, but they see the warning every time.

A precondition check is added: before invoking Claude, the runner verifies that `$PWD/.claude/agents/` exists. If absent, it exits with a friendly error:

```
Error: this workspace has not been initialised. Run 'reveng init' first.
```

This handles the case where a developer clones a reveng workspace from a colleague — `.claude/` is gitignored, so it won't be present, and the developer needs a clear pointer to `reveng init` rather than a cryptic Claude Code failure.

### Devcontainer

The `~/.config/reveng` bind mount is removed. Agents and skills now travel inside the workspace mount (which devcontainer already provides), so they are reachable at `/workspace/.claude/` inside the container.

The reveng binary mount stays — that's a separate concern and still required.

**Verification step:** before removing the mount, confirm that Claude Code running inside the devcontainer discovers `/workspace/.claude/agents/` and `/workspace/.claude/skills/` the same way it does on the host. If discovery requires a host-style `~/.claude/` location, the container config will need adjustment.

### Source of truth

`install.sh` continues to populate `~/.config/reveng/plugin/{agents,skills}/`. That directory is read by `reveng init` and no longer read by the runner. The path could be renamed (e.g. `~/.local/share/reveng/`) for clarity since it is no longer a "plugin" in the Claude Code sense, but this is cosmetic and out of scope here.

## What this replaces

| Before | After |
|--------|-------|
| Runner passes `--plugin-dir $PLUGIN_DIR` on every Claude invocation | Runner uses Claude Code's default `.claude/` discovery |
| Agents and skills hidden in `~/.config/reveng/plugin/` | Agents and skills visible in `$PWD/.claude/` |
| Plugin reachable from any directory the runner is invoked in | Requires `reveng init` to have run in the current workspace |
| Devcontainer bind-mounts `~/.config/reveng` | Devcontainer relies on workspace mount alone |

## Trade-offs

- **Discoverability gained** — primary objective, achieved.
- **Updates require re-running `reveng init`** — accepted. Local edits to copied agents are not preserved across re-init; users wanting persistent local tweaks must manage that themselves.
- **Conflict on re-init is silent (warning only)** — accepted. Skipping is the safest default; users can force a refresh by deleting `.claude/` and re-running init.
- **Workspace requires init before any reveng command runs** — accepted. The runner's precondition check makes this failure obvious.

## Out of scope

- Renaming `~/.config/reveng/plugin/` to a non-plugin path.
- Any change to the `.claude-plugin/` directory shipped in the source repo (still used by Claude Code marketplace tooling if ever published).
- A `reveng update` command to refresh `.claude/` in an existing workspace. Users currently re-run `reveng init` (and accept the skip-conflicts behaviour). If this becomes painful, revisit.

## Implementation order

1. Write the static workspace CLAUDE.md content (ships in repo, copied by init).
2. Update `cmd_init` in the `reveng` script to perform the copies and write `.gitignore` entries with the skip-on-conflict policy.
3. Add the precondition check to `run_claude` (or each `cmd_*` that invokes it).
4. Remove `--plugin-dir` from the runner's `claude` invocation.
5. Verify Claude Code inside the devcontainer discovers `/workspace/.claude/`. If yes, remove the `~/.config/reveng` mount from `cmd_sandbox`.
6. Update README and the `reveng-cli.md` spec to reflect the new model.
